# PRODUCT.md -- 产品描述

本文件只描述**用户可见的产品行为与需求**（界面、交互、展示规则、边界）。
实现方式、分层结构、数据落点、Provider 切换、API 契约与测试体系等一律见 `docs/ARCHITECTURE.md`；
实现变更不得改变本文件描述的用户可见行为——**行为要变，先改本文件**。

## 1. 产品定位
- 法律知识库 + 法律问答助手 Agent：根据用户问题给出法律问题回答，并保存用户的问题与回答。

## 2. 知识库（文档）
- 用户可以在前端界面中上传文档作为知识库内容，支持 PDF、TXT、MD 等格式；上传后的文档会被解析并纳入知识库，供问答检索使用。
- 对包含“第 X 条”法条边界的法律文本，知识库切分优先保持单条法条完整：短法条可以合并，超过目标长度的单条法条也不会在中间截断；普通非法律文本继续按段落和长度切分。
- 用户可以通过侧边栏的「知识库」按钮切换到知识库管理视图（与对话历史同处侧边栏）；侧边栏仅显示文档数量与处理状态汇总，不罗列文件名。
- 已上传文档的名称、大小、处理状态与删除操作，在主区域的知识库管理页查看和完成。
- 知识库文档列表按上传时间倒序展示：最新上传的文档排在最前面。

## 3. 对话
- 用户可以在前端界面中创建新的对话，并且可以在不同对话之间切换。
- 点击「新对话」进入空白对话界面；发送第一句提问时才真正创建会话，并以该提问内容（截短）作为会话标题，便于在历史列表中辨认（提问后标题不会再自动变化）。
- 点击「新对话」时，若当前处于知识库视图，自动跳转回对话视图（新对话是对话行为，不应停留在知识库页面）。
- 用户可以在对话内容区域中输入问题，模型回复以流式方式逐步显示。
- 生成过程中，回答上方显示「思考」块（浅色小字，默认展开），实时打印助手的执行过程，包括：工作环节与耗时（如「理解问题」「检索知识库」「校验回答依据」）、各环节的决策输出（意图判定、编排决策、证据评估、依据校验判定等）、检索运行细节（查询数、命中数、重排情况）、检索策略列表（本次使用的全部检索查询：原始问题、改写、子问题拆分、术语扩展；重新规划时该列表更新），以及回答重写与预算收尾等流转过程说明。
- 当本地配置主动关闭精排（`RERANK_ENABLED=false`）时，思考块显示「证据按融合排序完成（精排已关闭）」；这表示按配置使用 RRF 融合顺序，不表示模型故障。只有精排模型实际加载或推理失败时，才显示「证据重排失败，已降级为融合排序」。
- 「思考」块标题可点击展开或收起；回答输出完成后思考块自动收起为一行摘要（如「已完成思考 · 18.5s」），点击可重新展开查看完整过程；发起新提问时重新开始记录。
- 回答出错时思考块保留显示（可查看出错前执行到哪一步），错误提示单独显示。
- 思考内容仅在当前浏览期间保留：刷新页面或重新打开会话后，历史消息不显示思考块。
- 一般性对话（问候、概念解释、系统功能说明类问题）同样显示思考块，只是没有检索相关条目。
- 一般性对话（问候、概念解释、系统功能说明类问题）不经知识库检索直接回答，不显示检索策略列表；法律事实型问题默认检索知识库。
- 用户可以在输入框中点击「联网搜索」按钮切换联网搜索模式；按钮保持当前选中状态，直到用户再次点击关闭。
- 只有开启「联网搜索」模式并发送问题时，才会调用外部搜索；按钮关闭时，即使问题包含“最新”“搜索”等词，也不会访问网络，并提示用户先开启该按钮。
- 启用按钮时会检查联网搜索配置。未配置 `TAVILY_API_KEY` 时仍允许按钮切换，但界面显示 tag「需要配置 TAVILY_API_KEY」；发送时后端会再次校验并返回同样的提示。
- 联网搜索回答仍按照现有 Agent 流程生成和校验，不绕过思考块、回答校验或最终收尾；搜索完成后回答下方显示「联网搜索内容」折叠区。
- 「联网搜索内容」按搜索结果展示网页标题、可点击网页地址和内容摘要；每条内容最多显示 300 字，完整检索内容由后端单独保存。
- 联网搜索异常或搜索结果无法保存时，界面显示失败 tag，助手不编造外部结果；每次实际搜索都对应一个永久保留的独立后端日志文件。
- 回答在完成后会经过自动校验；校验未通过时回答会自动修正或补充检索后重新生成，生成中的内容会被清空重写，用户无需手动操作。
- 显示历史对话，可以删除对话。
- 侧边栏历史对话按创建时间从上到下排列：最早创建的在最上面，新创建的会话追加到最下面。
- 对话内容按发生时间从上到下正序展示：提问在上、对应回答在下。

## 4. 参考文档（回答依据展示）
- 当回答基于知识库检索（RAG）且检索有命中时，回答完成后下方显示「参考文档」按钮；点开后按序号展示参考的文档名称与对应命中内容（按相关性重排，最多 10 条），刷新或重新打开会话后仍可查看。
- 参考文档默认使用本地 llama serve Qwen3 Reranker GGUF 按用户原问题排序；模型正常工作时直接展示排序结果，主动关闭或模型服务故障时分别按思考块中的对应文案说明并继续使用 RRF 顺序。
- 检索到部分相关证据时，回答会基于已有证据谨慎作答并正常展示参考文档；完全无命中时回答明确声明"知识库中暂无相关依据，建议咨询专业律师"，不显示「参考文档」按钮。
- 当回答未使用知识库检索（直接回答）或检索无命中时，不显示「参考文档」按钮。

### 4.1 联网搜索内容
- 「联网搜索内容」与「参考文档」是两类独立来源展示，不混用折叠区；历史消息恢复后仍可查看联网搜索内容。
- 搜索来源只展示后端返回的合法 HTTP/HTTPS 地址；地址以新标签页打开，并保留网页标题和 300 字以内的纯文本摘要。

## 5. 视觉与交互风格
- 界面设计风格与功能类似 Codex 网页版：审美高（接近苹果与 Claude 的设计语言），交互简单。

## 7. 开发者侧 RAG 评测边界

RAG 评测系统用于评估生成答案的质量、回归验证和失败分析，不是终端用户功能，不改变对话页面和公开问答接口。

- 向量库默认连接 Milvus Cloud；开发者通过 `MILVUS_PROVIDER=local` 显式切回本地 standalone。两种部署对用户侧上传、检索和参考文档展示行为保持一致。当前主 LLM 默认使用 DeepSeek；也可通过 `LLM_PROVIDER` 切换 Provider，DeepSeek 思考模式固定关闭。

- 评测使用仓库内的法律测试文档，并复用当前 Milvus 集合和 SQLite 数据库；默认不清理数据，只有显式执行 `prepare --reset` 才会删除当前数据库中的全部文档，因此重置只适合可重建的测试知识库。
- 真实质量评测固定使用 DeepSeek 主 LLM + Milvus + llama serve Qwen3 Reranker；Embedding 使用 llama serve Qwen3 Embedding。Ollama/GLM 对话 Provider 的协议测试与质量评测隔离。模型和网络具有波动性，报告用于展示趋势与失败案例，不把单次分数伪装成绝对正确率。
- 评测结果输出 JSON 和 Markdown；不新增评测前端页面，不把密钥、Authorization 或完整敏感配置写入报告。
- 质量评测直接调用工作流，依据问题、答案要点、检索证据和最终回答评估正确性、完整性、依据支持及引用准确性；检索与 grounding 指标辅助定位问题。评测入口只保留数据准备和质量评测，不包含 API/SSE 冒烟测试。
- 评测 Judge 默认复用 DeepSeek 主 LLM；需要隔离评测模型时，真实质量评测只允许通过 `EVAL_JUDGE_PROVIDER=deepseek` 与 `EVAL_JUDGE_MODEL` 配置，其他 Provider 不参与质量评测。
- `LANGFUSE_ENABLED` 默认开启；密钥缺失或 Langfuse 不可达时仅记录 WARN 并降级，不阻断终端问答。评测每条案例会记录独立 trace 和 Judge span；报告中的 trace ID 只用于开发者排障，不改变终端问答行为。
- 评测恢复轮会保留缺失证据中的法条号、期限和主体等关键锚点，扩大召回后再统一精排；主图和 RAG 子图的节点、边及恢复流程不变。
- 评测 Judge 遵循产品引用协议：`【来源：文件名】` 与证据来源一致即可，不把“未要求引用”的直接回答因无本地证据判为不 grounded；期望状态与实际状态不一致时不通过。
