# ADR-0009：思考块（Thinking Panel）与 think 事件——过程展示从"节点状态"升级为"过程内容"

- 状态：Accepted（2026-09-13）
- 关联：docs/PRODUCT.md §3、docs/ARCHITECTURE.md §7、BE-042/FE-016、plan.md 决策 D6~D12、ADR-0002（SSE 向后兼容口径）、ADR-0008（status 事件机制）

## 背景

BE-041/FE-015 已把节点起止状态以浅色小字流式展示（status 事件），FE-014 有独立的「检索策略」面板（plan 事件）。用户提出三点升级：①浅色过程信息统一归类为一个可点击折叠的「思考」块（默认展示，答案输出完整时收起为一行）；②浅色字不仅表示运行节点，还要把**运行内容与 LLM 输出**打印出来（决策输出、检索细节、重写/兜底过程）。现有 status 事件只有 node/label/phase/duration_ms，没有内容通道；plan 面板游离在状态行之外；出错时前端清空过程记录，用户无法看到出错前走到哪一步。

## 决策

1. **统一「思考」块容器（FE-016）**：节点状态行（status）、检索策略（plan 的 sub_queries）、新增内容行（think）三类浅色行聚合在回答上方同一容器内，生成中默认展开；回答完成后**自动收起为一行**「已完成思考 · Ns」（墙钟时间），点击可再展开/收起（DeepSeek 式交互，D6/D7）。
2. **新增 think 事件（BE-042，字段只增不改）**：`{"type": "think", "node", "label", "text"}`——node=产生节点，label 复用 NODE_LABELS 中文映射，text=已截断的内容文本。与 status 互补：status 表节点起止，think 表过程内容；同一节点可发多条。ChatService/SSE 路由增显式分支（仅转发，不进 delta 聚合）；旧前端静默忽略未知事件类型（ADR-0002 口径）。
3. **内容产自节点内部，不造新机制**：think 由各节点经既有 `emit_event`（ContextVar 发射器，ADR-0008）发送——只有节点知道自己的业务内容，包装器（with_node_status）保持只管起止状态不越权。节点→内容清单见 plan.md（query_router=意图判定、orchestrator=编排决策、hybrid_retriever=命中数、evidence_grader=评估结论、grounding_checker=判定+理由、stub=未开通说明、final_answer=来源条数等；observation/direct_answer/answer_generator 不发，避免与回答本体重复）。
4. **原文截断打印 + JSON 拼句（D9）**：非结构化 LLM 输出（如 grounding 校验理由）直接打印原文；结构化 JSON 输出（意图/编排/评估等 structured_invoke 结果）把关键字段拼成一句中文再打印。统一 `truncate_text(text, 120)`（agent/utils），**后端发事件前截断**——契约保证 text ≤120 字，前端零截断逻辑，单一事实源在后端。
5. **流转过程单一事实源在后端**：regenerating/兜底触发等流转由后端发 think（前端不自行合成文案）。
6. **生命周期**：思考行仅存客户端内存（新提问清空、done 后快照挂到消息、**出错时保留不清空**——现状清空行为移除，D12）；刷新页面后历史消息不显示思考块，不改数据库 schema（D10）。闲聊直接回答路径同样展示思考块（行数少、无检索条目，D11）。

## 备选与取舍

- **扩展现有 status 事件加 detail 字段**：会混淆"节点起止"与"过程内容"两种语义（status 同节点仅 start/end 两帧，think 可多条），消费端合并逻辑复杂化——否。
- **前端合成流转文案/前端截断**：文案与截断规则散落两处，违背单一事实源——否。
- **思考内容持久化到数据库**：需改消息表 schema + 历史消息 API + 前端恢复，用户已明确刷新后不保留——否（后续如需，think 行随消息快照存 JSON 是自然扩展点）。
- **LLM 输出全摘要化**：实现成本高且丢失原文细节，用户明确选原文截断——否。

## 后果

- 正向：过程展示从"黑盒节点名"升级为可读的决策与运行细节；检索策略/状态/内容归一交互；出错可诊断性提升（保留到最后一步）；SSE 契约仍向后兼容。
- 代价：每问题 SSE 帧数增加约 10~15 帧（单帧 <300 字节，可接受）；各节点新增 emit 调用与拼句逻辑（测试锁定）；前端 FE-015 的 nodeStatuses 双状态升级为统一思考行列表（同节点合并 + 追加）。
- 中性：text ≤120 字为硬契约，超长理由尾部丢失（可接受的展示性截断，完整理由仍在后端日志/trace）。
